# Инструкции для агента (генератор лендингов 2GIS)

## Роль
Ты собираешь лендинги 2GIS из готовых блоков, строго следуя дизайн-системе.
Ты не дизайнер: ты не придумываешь значения, а берёшь их из файлов репозитория.

## Структура проекта и как с ней работать
- `.qwen/` — служебная папка агента:
  - `.qwen/AGENT.md` — этот файл с инструкциями;
  - `.qwen/README.md` — описание папки;
  - `.qwen/context/design-rules.md` — дизайн-правила: палитра, типографика,
    отступы, радиусы, роли цветов. Любую работу начинай с чтения этого файла.
- `patterns/` — строгие повторяющиеся (канонические) блоки:
  - хедер: документ `patterns/header.md` (ключевые значения и правила)
    + реализация `patterns/header/header.html` и `patterns/header/header.css`;
  - футер и другие канонические блоки — по мере появления, в том же формате
    (документ + файлы реализации).
- `blocks/` — примеры экранов (hero, features, pricing, cta и т.д.).
  Берутся за основу секций и адаптируются под задачу по контенту, но не по стилям.
- `assets/` — логотипы, интерфейсные изображения, картинки. Используются только отсюда.
  Сейчас: `assets/logo/logo-dark.svg` — единственный логотип (все лендинги тёмные).
- `scripts/` — скрипты сборки и проверок. Запускаются, руками не редактируются.
- `dist/` — результат сборки: готовые лендинги и копия ассетов (`dist/assets`).
  Руками не редактируется.

## Источник истины (приоритет сверху вниз)
1. `patterns/` — для канонических блоков: разметка и стили копируются дословно.
2. `.qwen/context/design-rules.md` — значения цветов, кеглей, отступов, радиусов.
3. Стили экранов в `blocks/` — как образец применения правил.
При противоречии файлов между собой верен файл с более высоким приоритетом.
Никогда не придумывай значения. Нет значения в этих файлах — остановись и спроси.

## Канонические блоки (patterns/)
- - Хедер — ТОЛЬКО из `patterns/header/`:
  - документ: `patterns/header/header.md` (ключевые значения и правила);
  - реализация: `patterns/header/header.html` + `patterns/header/header.css`.
- - Футер — ТОЛЬКО из `patterns/footer/`:
  - документ: `patterns/footer/footer.md`;
  - реализация: `patterns/footer/footer.html` + `patterns/footer/footer.css`.
- Копировать разметку и стили дословно, посимвольно.
- Разрешено менять: href ссылок, тексты ссылок и кнопок, alt логотипа.
- Запрещено: менять структуру, размеры, зазоры, радиусы, цвета; добавлять и удалять
  элементы; «улучшать» и перекомпоновывать.
- Если нужного паттерна нет (например, ещё не создан футер) — остановись и запроси
  его у пользователя; НЕ создавай канонический блок сам.

### Ключевые значения хедера (справочно, источник — patterns/header.md)
- header-top: высота 56px — логотип, поиск, язык, кнопки.
- header-nav: высота 80px, фон #283136, radius 16px; дропдаун «Все продукты»
  + ссылки навигации.
- Контейнер: 1168px.
- Скругления: кнопки 12px, поиск 12px, nav-панель 16px.
- Навигация: 16px (body-md), gap 32px, цвет rgba(255,255,255,0.64), hover #FFFFFF.
- Кнопка «Оставить заявку»: фиксированная ширина 190px.
- Логотип всегда ссылка на главную; дропдаун «Все продукты» — единственный
  раскрывающийся элемент хедера.

## Экраны (blocks/)
- Секции лендинга собираются из примеров экранов в `blocks/`.
- Адаптация под задачу: контент, количество карточек, тексты, порядок секций —
  по согласованию с пользователем; стили блока не меняются.
- Стили экранов — только через var(--…) переменные из design-rules.md.
- Нет подходящего примера экрана — спроси пользователя, не изобретай новый стиль.

## Ассеты (assets/)
- Логотипы, иконки, картинки — только готовыми файлами из `assets/`.
- Логотип: единственный файл `assets/logo/logo-dark.svg`; не перекрашивать,
  не перерисовывать, не масштабировать вне заданных высот.
- `dist/assets/` — копия ассетов, создаваемая сборкой для самодостаточности
  лендинга; руками не редактируется и не пополняется: источник всегда только
  корневой `assets/`.
- Запрещено: внешние ссылки на картинки, генерация изображений с нуля,
  перекраска через CSS-фильтры.

## Жёсткие правила
1. Цвета — только из палитры design-rules.md, через var(--…). Никаких своих
   hex/rgba/hsl в стилях блоков.
2. Шрифт — только "Suisse Intl", без фолбэк-стеков в font-family.
3. Скругления: кнопки и инпуты 12px, карточки 12px, крупные карточки и панели 16px,
   nav-панель 16px. Никаких pill (9999px).
4. Primary-кнопка — брендовый тёмно-зелёный #12951A (через var) с белым текстом.
   Никогда серая/белая/чёрная.
5. Ссылки и акцентный текст на тёмном — светло-зелёный #3BB643 (через var);
   #12951A для текста на тёмном не использовать.
6. Элевация — только через контраст поверхностей. Тени не использовать.
7. Текст — иерархия с прозрачностью 100 / 64 / 36 (через var).
8. Лендинги собираются ТОЛЬКО в тёмной теме (`<html data-theme="dark">`).
   Светлая тема в лендингах не используется.

## Workflow сборки лендинга
1. Прочитать `.qwen/context/design-rules.md`.
2. Согласовать состав секций с пользователем или взять набор экранов из `blocks/`.
3. Вставить хедер дословно из `patterns/header/` (header.html + header.css).
4. Вставить футер дословно из `patterns/footer/` (footer.html + footer.css).
5. Собрать секции из примеров `blocks/`, заполнить контентом пользователя.
6. Подключить логотип и изображения из `assets/`.
7. Собрать результат в `dist/` скриптами из `scripts/`.
8. Прогнать чек-лист самопроверки; найденное исправить ДО выдачи результата.

## Чек-лист самопроверки
- [ ] Хедер совпадает с `patterns/header/` дословно, без перекомпоновки.
- [ ] Футер совпадает с `patterns/footer/` дословно (если паттерн существует).
- [ ] header-nav: высота 80px, align-items: center, фон #283136, radius 16px.
- [ ] Логотип: единственный файл `assets/logo/logo-dark.svg`, ссылка на главную.
- [ ] Primary-кнопка: #12951A (через var), radius 12px, белый текст.
- [ ] Нет hex вне блоков объявления переменных.
- [ ] Нет теней, pill-радиусов, фолбэк-стеков.
- [ ] font-family: только "Suisse Intl".
- [ ] Все изображения и логотип взяты из `assets/`, внешних ссылок нет.
- [ ] Ассеты в `dist/` появились копией из корневого `assets/`, а не созданы вручную.
- [ ] Сборка выполнена скриптами из `scripts/`, результат лежит в `dist/`.
- [ ] Файл лендинга открывается локально без сервера.

## Формат блоков (для blocks/)
Каждый блок содержит: когда использовать; HTML-структуру с {props}; список props;
стили через var(--…); правила использования; do/don't.
