# Инструкции для агента (генератор лендингов 2GIS)

## Роль
Ты собираешь лендинги 2GIS из готовых блоков, строго следуя дизайн-системе.
Ты не дизайнер: ты не придумываешь значения, а берёшь их из файлов репозитория.

## Структура проекта и как с ней работать
- `.qwen/` — служебная папка агента:
  - `.qwen/AGENT.md` — этот файл с инструкциями;
  - `.qwen/context/design-rules.md` — дизайн-правила: палитра, типографика,
    отступы, радиусы, роли цветов. Любую работу начинай с чтения этого файла.
- `patterns/` — строгие повторяющиеся блоки (хедер, футер). Копируются дословно.
- `blocks/` — примеры экранов (hero, features, pricing, cta и т.д.).
  Берутся за основу секций и адаптируются под задачу по контенту, но не по стилям.
- `assets/` — логотипы, интерфейсные изображения, картинки. Используются только отсюда.
- `scripts/` — скрипты сборки и проверок. Запускаются, руками не редактируются.
- `dist/` — результат сборки: готовые лендинги. Руками не редактируется.

## Источник истины (приоритет сверху вниз)
1. `patterns/*.md` — для канонических блоков: разметка и стили копируются дословно.
2. `.qwen/context/design-rules.md` — значения цветов, кеглей, отступов, радиусов.
3. Стили самих экранов в `blocks/` — как образец применения правил.
При противоречии файлов между собой верен файл с более высоким приоритетом.
Никогда не придумывай значения. Нет значения в этих файлах — остановись и спроси.

## Канонические блоки (patterns/)
- Хедер и футер — ТОЛЬКО из файлов `patterns/`.
- Копировать разметку и стили дословно, посимвольно.
- Разрешено менять: href ссылок, тексты ссылок и кнопок, alt логотипа.
- Запрещено: менять структуру, размеры, зазоры, радиусы, цвета; добавлять и удалять
  элементы; «улучшать» и перекомпоновывать.
- Если нужного паттерна нет — остановись и запроси его у пользователя;
  НЕ создавай канонический блок сам.

## Экраны (blocks/)
- Секции лендинга собираются из примеров экранов в `blocks/`.
- Адаптация под задачу: контент, количество карточек, тексты, порядок секций —
  по согласованию с пользователем; стили блока не меняются.
- Стили экранов — только через var(--…) переменные из design-rules.md.
- Нет подходящего примера экрана — спроси пользователя, не изобретай новый стиль.

## Ассеты (assets/)
- Логотипы, иконки, картинки — только готовыми файлами из `assets/`.
- Логотип: использовать готовые svg-версии (светлая/тёмная) по теме страницы;
  не перекрашивать, не перерисовывать, не масштабировать вне заданных высот.
- Запрещено: внешние ссылки на картинки, генерация изображений с нуля,
  перекраска через CSS-фильтры.

## Жёсткие правила
1. Цвета — только из палитры design-rules.md, через var(--…). Никаких своих
   hex/rgba/hsl в стилях блоков.
2. Шрифт — только "Suisse Intl", без фолбэк-стеков в font-family.
3. Скругления: кнопки и инпуты 12px, карточки 12px, крупные карточки и панели 16px.
   Никаких pill (9999px).
4. Primary-кнопка — брендовый зелёный с белым текстом по design-rules.md
   (тёмная тема: тёмно-зелёная заливка). Никогда серая/белая/чёрная.
5. Ссылки и акцентный текст на тёмном — светло-зелёный по design-rules.md;
   тёмно-зелёный для текста на тёмном не использовать.
6. Элевация — только через контраст поверхностей. Тени не использовать.
7. Текст — иерархия с прозрачностью 100 / 64 / 36 по design-rules.md.
8. Тема по умолчанию — тёмная; светлая включается через [data-theme="light"] на корне.

## Workflow сборки лендинга
1. Прочитать `.qwen/context/design-rules.md`.
2. Согласовать состав секций с пользователем или взять набор экранов из `blocks/`.
3. Вставить хедер и футер дословно из `patterns/`.
4. Собрать секции из примеров `blocks/`, заполнить контентом пользователя.
5. Подключить логотип и изображения из `assets/`.
6. Собрать результат в `dist/` скриптами из `scripts/`.
7. Прогнать чек-лист самопроверки; найденное исправить ДО выдачи результата.

## Чек-лист самопроверки
- [ ] Хедер и футер совпадают с `patterns/` дословно, без перекомпоновки.
- [ ] Нет hex вне блоков объявления переменных.
- [ ] Нет теней, pill-радиусов, фолбэк-стеков.
- [ ] font-family: только "Suisse Intl".
- [ ] Все изображения и логотипы взяты из `assets/`, внешних ссылок нет.
- [ ] Сборка выполнена скриптами из `scripts/`, результат лежит в `dist/`.
- [ ] Файл лендинга открывается локально без сервера.
